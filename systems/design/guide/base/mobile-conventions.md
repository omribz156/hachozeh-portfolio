# Mobile conventions

The platform is a real mobile build (fluid root scale, bottom-tab thumb nav, safe-area-aware chrome), not a desktop layout squeezed down. These are the cross-cutting rules that keep new surfaces inheriting the polish instead of re-inventing it. Pairs with [css-base-contract.md](./css-base-contract.md).

Lens for every mobile decision: **one hand, one thumb, outdoors, mid-range phone, flaky connection.**

## The foundation (set once, inherited everywhere)

- **`viewport-fit=cover` is mandatory.** It lives in `Layout.astro` + `HelpLayout.astro`. Without it every `env(safe-area-inset-*)` resolves to `0` on notched iPhones — the bottom tab bar and trade launcher silently stop clearing the home indicator. Don't remove it.
- **Use `100dvh`, not `100vh`,** for any full-height surface (overlays, FX canvases, loading states). `100vh` sizes past the visible area when the iOS browser bar is shown. Fallback pattern: `height: 100vh; height: 100dvh;`.
- **Safe-area insets** belong on anything pinned to a screen edge. The shared overlay shell (`base/primitives.css` `.navi-overlay-shell`) already pads by `max(space, env(safe-area-inset-*))`; centered modals built on it are covered. Bottom-pinned chrome adds `env(safe-area-inset-bottom)` itself.

## Touch feel

- **Tap feedback is global, touch-only.** `global.css` carries one unlayered rule (same model as `:focus-visible`): under `@media (hover: none) and (pointer: coarse)`, interactive elements get an instant press state (opacity dip + a scale on box-like controls). Low specificity on purpose — a component's own `:active` (loaded later in patterns/) always wins, so bespoke press states keep their feel. **Prefer adding a component `:active` over fighting the global one.**
- **All `:hover` is gated behind `@media (hover: hover)`.** This is the complement of the press convention above: hover effects fire only on real pointers, so on touch there's no iOS sticky-hover and no component hover-lift outranking the press-scale. **Author every new hover rule inside `@media (hover: hover)`** — never a bare `:hover`. If a rule combines `:hover` with `:focus`/`:focus-visible`, split it: gate the `:hover`, leave the focus selector ungated so keyboard/focus still works everywhere.
- **44px touch-target floor** (Apple HIG / WCAG 2.5.5) — **reach it with an invisible hit-area, never by inflating the visible control.** Visible control dimensions follow the surface's own density at every breakpoint; growing a control's painted box to hit 44px reads as bloat (owner calibration verdict, 2026-07). The pattern: `position: relative` on the control + a centered `::before` under `@media (hover: none) and (pointer: coarse)` with `content: ""`, `position: absolute`, `top/left: 50%`, `transform: translate(-50%, -50%)`, and `width`/`height` set to the target size — no visual properties (background, border) on the pseudo-element. Reference implementation: `.hz-shell__cat-item` in `patterns/site-shell.css`. When adjacent controls sit close enough that a full 44×44 hit-area would cross into a neighbor's visible box, cap the dimension(s) facing that neighbor (e.g. `width: 34px` instead of `44px`, keep `height: 44px` if there's no vertical neighbor) — same-type, low-stakes groups (filter chips, tabs, range pills) can accept the DOM-order-wins overlap uncapped, but a pair of opposing real actions (e.g. a כן/לא or buy/sell button) must never let one control's hit-area sit above its neighbor's visible box. `.hz-tap-min` (`global.css`) is the drop-in utility for the uncapped case; hand-roll the capped `::before` for adjacency-sensitive pairs.
- **`touch-action: manipulation`** is set on real controls in `base/reset.css` (kills the legacy 300ms delay + double-tap-zoom). The tap-highlight flash is reset there too, broadened beyond `button`/`a`.
- **Inputs must be ≥16px** on a focusable field, as a **literal px** — the root scale clamps to ~14.5px at phone width, so `1rem`/`0.9rem` still trip iOS focus-zoom (which sticks after the field closes, panning the page out of bounds). Set `font-size: 16px` on the focusable input. If the design wants a smaller size at rest (e.g. a compact `select`), iOS only reads the computed size **at the moment focus lands** — so scope the 16px floor to a `:focus` rule (`.foo select:focus { font-size: 16px; }`) instead of the base rule; the resting text keeps its smaller design size and the zoom is still fully suppressed. `check-input-font-size.sh` recognizes this paired shape and won't flag the rem/em base rule as a violation.

## Bottom sheet (the trade ticket)

The mobile trade ticket is a **bottom sheet**, not a centered modal (`pages/market-detail.css`, `@media (max-width: 960px)`):

- Pinned to the bottom edge, full-bleed on phones / `max-width` centered on tablets, rounded top, drag-handle affordance (`::before`), `env(safe-area-inset-bottom)` padding. The **confirm button lands in the natural thumb arc** at the sheet's foot.
- Slides up from `translateY(100%)`; the scrim's `visibility` transition is matched to the slide so the close animation isn't clipped.
- **Swipe-down-to-dismiss** (`markets/[marketKey].astro`): engages only at the sheet's scroll-top with a downward drag (so it never steals internal scroll); `.is-dragging` kills the transition for 1:1 tracking, release closes past threshold or snaps back.
- **Closes after a successful trade** — the page listens for the `hz:trade-complete` event and closes the sheet ~1.3s later, after the commit celebration plays. Closing also fires `hz:trade-ticket-close`, which the ticket island handles by **wiping the amount** so it reopens blank.
- **Sheet layout is reordered + deboxed** (Poly-leaning, all `@media (max-width: 960px)` in `trade-ticket.css`, scoped to `.market-detail-stage-order-widget` so the desktop rail is untouched). Flow: Buy/Sell (top-left) → market header → centered hero amount (`V₪` left, LTR) → wallet line → outcomes → to-earn + price-per-share (centered, pop in on quote) → money chips → submit. Leaf order is achieved by `display: contents` on the `.space-y-3` wrapper so CSS `order` can interleave it with the outcome sibling.
- **Buy/Sell and the outcomes are sliding "swap toggles"** — a pseudo-element thumb (`::before`) driven by the ticket's `data-order-side` / `data-active-side`, animated with `translateX`. The outcome thumb tints to the active team color (`--cta-team` via `color-mix`). Buy/Sell is absolutely positioned top-left; the header reserves its footprint with `padding-inline-end` so long titles ellipsize before it.
- **Quick chips are `+ V₪ N` increment chips that STACK** (`TradeTicket.jsx` `handleChipClick` adds onto the running amount), `direction: ltr` for canonical money order; the "all"/% chips still set. The to-earn footer holds its last value while the next quote loads (stale-while-revalidate via `showSummary`), so changing the amount never wipes/flashes the price.
- Per-outcome **crest images are all mounted and toggled by opacity** (not `src`-swapped) so switching sides never re-fetches the flag — instant even under the dev `no-store` header.

## Signature moments share one FX vocabulary

The **trade commit** and the **win reveal** both use `window.HZStreakFX` (confetti/spark burst + `countUp`), reduced-motion-safe, so a win feels like the sequel to the bet. The result reveal counts the payout up from 0 and bursts in the brand palette; loss stays calm (no confetti). A **win now auto-surfaces** the moment its resolution lands over the live channel (gated; see "Known follow-ups"); a loss never does. Reuse `HZStreakFX` for future celebratory moments rather than hand-rolling FX.

The win reveal's primary action is **אסוף עכשיו** (collect now), wired in `result-overlay.js`: it resolves the pending claim by `marketKey` via `GET /api/portfolio/claims`, `POST`s `/api/portfolio/claims/:claimId/claim`, then fires `wallet:credited` + `navi:portfolio-snapshot-updated` and flips the button to **✓ נאסף!**. The notification (`notifications.client.js`) passes `marketKey`; `?resultDemo=win` simulates the claim for preview.

## Known follow-ups (deferred deliberately)

- ~~**Auto-surface the result reveal on resolution.**~~ **Done (wins only, gated).** When a `win` resolution lands over the live notification stream (`header-session.client.js` → `notifications.client.js` `refresh()`), the result reveal pops the moment it arrives — the win is the sequel to the bet. **Losses never auto-pop** (rubbing it in violates calm-on-loss); they stay in the bell, pull-not-push. Two invariants in the controller: (1) **prime, don't pop history** — the first `refresh()` records the existing inbox as `seen`; only ids that appear *after* priming auto-pop (mount-once + `transition:persist` keeps `primed` across soft-nav, so navigation never re-pops). (2) **never interrupt** — `screenBusy()` (any `body.overlay-open` / visible `[role=dialog][aria-modal]` / mid-input / backgrounded tab) defers the win into a queue, and a body `MutationObserver` — live *only* while something is queued — flushes it the instant the screen frees. Verified end-to-end on the authed live SSE path (prime/pop/defer/flush/loss-never).
- ~~**`@media (hover: hover)` gating sweep.**~~ **Done.** Every `:hover` rule in `src/styles` (246 rules across 38 files) is now wrapped in `@media (hover: hover)`, so hover effects fire only on a real pointing device. On touch this kills iOS sticky-hover (a tapped card no longer keeps its hover state) and stops component hover-lifts from beating the global press-scale — the `@media (hover: none) and (pointer: coarse)` press convention is now the sole touch affordance. Combined `:hover, :focus-visible` selectors were **split** (19 of them): the `:focus-visible` half stays ungated so keyboard focus keeps the effect on every device; only the `:hover` half is gated. Done as a postcss codemod (deterministic split + in-place wrap, cascade-preserving), verified by a postcss assertion that **0 ungated `:hover` rules remain** and by browser checks (desktop: card hover-lift still fires; touch: `hover:hover` does not match). New CSS must follow this — author hover rules inside `@media (hover: hover)`, never bare.
- ~~**SSE visibility pause + script deferral.**~~ **Done.** The nine always-on feature scripts in `Layout.astro` now carry `defer` (off the critical path, order preserved for the daily-streak init trio; helps desktop too). The discovery feed's `EventSource` (`FeedPage.astro`) now drops on `document.hidden` and reopens on return via an armed `reopen` handle — the fresh connection's snapshot IS the catch-up — so a backgrounded tab no longer burns data or returns to a silently-dead zombie stream. The **market-detail price stream** (`markets/[marketKey].astro`) now gets the same treatment (a `document.hidden` guard in `connect()` + a `visibilitychange` handler that `close()`s on hide and `sync()`s on return). **Still open:** `breaking-markets.astro` has its own `EventSource` — deferred to its own pass.
- **Google Fonts are de-blocked, CSP-safely.** Both Google Fonts stylesheets load as `media="print"` (non-render-blocking) and a small inline `<script>` promotes them to `media="all"` on load. **Do NOT use an inline `onload="this.media='all'"` attribute** — the site CSP (`script-src-attr 'none'`) silently blocks inline event handlers, leaving the sheet stuck on print (it only rendered by a Chromium @font-face quirk; iOS WebKit would break). De-block via a `<script>` block + `addEventListener`, never an `onX=` attribute. Safe here because `display=swap` + the metric-matched fallback already paint correct text with no FOIT/shift.
- ~~**Per-surface tap-target sweep.**~~ **Mostly done, converted to the `::before` hit-area pattern (round 2 calibration).** A first pass floored controls with a bare `min-height`/`min-width: 44px`; the owner's on-device verdict was that the visible growth reads as bloat, so every one of those floors listed below was reverted to its original visible size and re-floored via the invisible-hit-area technique (see the doctrine bullet above): market-card primary CTAs (`.hz-yn .hz-yn__btn`, `.hz-tm__btn`, and the dense inline ladder `.hz-yn-inline .hz-yn__btn` — the ladder also got a modest text bump, 0.74rem→0.8rem, as its owner-approved density lever); the card bookmark (already used the `::before` pattern from the start); trending chips (`.hz-trending__chip`) and range/settings controls on the market-detail chart (`.chart-card__range-tab`, `.chart-card__settings-button`); portfolio `.pf-tab` + `.pf-timeframe`; community composer tools (`.xc-tool`, `.xc-add`/`.thc-add`). Hit-areas are capped on one axis wherever an adjacent control could otherwise sit above a neighbor's visible box (notably the כן/לא and team-pick pairs); same-type low-stakes groups (chip rails, tab lists, range pills) stay uncapped, matching `.hz-shell__cat-item`. **Left as bare `min-height`/`min-width` (out of this round's scope, flagged for a future pass):** viewer-positions sell (`38px→44px`, always-on — it's a money tap, arguably a deliberate exception rather than a bug); `.hz-result__btn` on the win/loss reveal (always-on, not touch-gated); `.hz-notif__dismiss` / `.hz-notif__settings` / `.hz-dispute__btn` in the central touch-floor block in `global.css`. **Two deliberate deferrals unchanged:** (1) the **invalid `<button>`-in-`<a>`** card nesting — the proper fix is the stretched-link restructure (card `<div>` + absolutely-positioned link layer + `z-index` on every control), which interacts with the press-feedback and click handling across all five card variants, so it wants its own verified slice; (2) the `iOS input auto-zoom` 16px floor now has a lighter-weight variant too — see the input rule below.
- **Expose `claimId` on win notifications.** The collect-now button re-fetches `GET /api/portfolio/claims` to map `marketKey`→`claimId` because the feed item doesn't surface the row's `realization_event_id`. Exposing it on the notification payload would drop the extra request.
- **Verify the real authed collect end-to-end.** Only the `?resultDemo=win` simulated path and the wiring were browser-verified; a logged-in account with an actual pending win (real money movement) hasn't been run through `אסוף עכשיו` live.
